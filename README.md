# The Unsleeping City: interactive route map

**Live map: https://breadlam.github.io/unsleeping-city-map-tour/**

A zoomable map of every place the player characters visit in Dimension 20's *The Unsleeping City*
(Chapters 1 and 2), and the routes they take between scenes. It is a static site: four files and no build step.

| File | |
|---|---|
| `index.html` | The page |
| `app.js` | The map logic |
| `style.css` | Layout and light/dark themes |
| `data.js` | All scenes, places and routes (about 450 KB), generated by `build_web.py` |
| `.nojekyll` | Tells GitHub Pages to serve the files as they are |

Leaflet 1.9.4 loads from cdnjs, with integrity hashes. Basemap tiles come from Esri and OpenStreetMap. Nothing else is fetched.

## Publish on GitHub Pages

1. Create a new GitHub repository and upload the contents of this folder to its root (including `.nojekyll`).
2. In the repository, open **Settings → Pages**. Under **Build and deployment**, pick **Deploy from a branch**,
   choose `main` and `/ (root)`, and save.
3. After a minute the map is live at `https://<your-user>.github.io/<repo>/`.

To put it inside an existing repository instead, copy the files into a `docs/` folder and pick `/docs` in step 2.

## Run it locally

Open `index.html` in a browser. It works straight from the file, because the data loads as a script rather than with `fetch`.
The basemap tiles still need an internet connection.

## Using the map

- **Timeline bar** (bottom): step through all 340 scenes in story-world order with the arrow buttons or the ← and → keys.
  Press play (or the space bar) to animate them, and drag along the strip to scrub. Each band in the strip is one episode.
  Chapter 1 is blue, Chapter 2 purple, and Kingston's 1994 flashback tan.
- **All / So far / This day** chooses which routes to draw: the whole story, only up to the current scene, or only the
  current scene's day.
- The route into the current scene is drawn bold with a white outline. Lettered dots show where each character is.
  A faded dot with a dashed border is where that character was last placed.
- **Pins**: click one for every scene at that place. Click a scene id to jump to it. Red pins are known positions,
  gray ones are approximate, and purple ones are Nod scenes pinned at the real place they mirror.
- **Lines**: click any route to see who travelled, how, and between which scenes. Strong lines mean the episode says
  how they travelled. Faded lines mean the mode was inferred. Parallel lines are characters travelling together.
- **Left panel**: filter by character ("only" isolates one), by chapter and by travel mode, and browse the scene list.
- **Layers** (top right): Streets, Light gray, Dark gray, OpenStreetMap or Satellite basemaps. Fit (⤢) zooms to everything shown.

### Shareable links

The address bar keeps the current state, so any view can be linked:

```
index.html#scene=C2E05-S07
index.html#scene=C1E09-S03&chars=Pete,Kingston&ch=1&show=upto
```

`scene` is an event id from `events.csv`. `chars` is a comma-separated list of Ricky, Sofia, Kingston, Misty, Kugrash, Pete, Iga, Cody.
`ch` is `1` or `2`. `show` is `upto` or `day`.

## Rebuilding `data.js`

Run this from the `Location Timeline` folder:

```bash
python3 source/scripts/build_web.py travel_routes.geojson events.csv interactive_map/data.js
```

If you change the scene notes, first rebuild `events.csv` with `compile.py` and the routes with `legs.py` and
`legs_to_geojson.py` (see the main README). `build_web.py` also accepts the `legs.json` that `legs.py` writes.

`build_web.py` needs only the Python 3 standard library. It simplifies the route geometry to about 2 m and stores it as encoded polylines.
